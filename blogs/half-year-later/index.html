    半年没更新：实习、大创赛，和那个不忍心删掉的第一版

    Daylight-by
    2026年10月22日星期四
    1 min read

    时隔小半年，终于又上来发一篇了。

    建博客那会儿的热情是真的，后来的懈怠也是真的 —— 好像还真应了那句话：得到了就不珍惜。

    这次为什么上线？就是想记录一下这半年发生的事，免得再过半年自己都忘了。

    那个没完成的计划

    说来惭愧。原本打算实习期间把网络安全学起来，路线都排好了：网络基础 → Linux → OWASP Top 10 → 工具链 → 靶场。

    结果现在回头看，完成度约等于零。

    原因也不复杂，我高估了自己的勤奋。上班一天回来，能打开电脑写两行代码就已经是胜利，更别提系统性地啃漏洞原理、搭靶场复现了。计划落空是事实，我不打算把它包装成什么"遗憾"。

    暑假找了个实习，公司不大。具体做了什么回头单独写一篇，这里先不铺开 —— 但学到的东西确实不少，总的说来是值的。

    大创赛要交了

    最近大创赛到了提交节点，我赶紧把大二做的那个酒店管理系统翻出来，想拿去交。

    重新拉下来看的时候，说实话有点不好意思。

    做得确实丑：

    • 页面是 Thymeleaf 服务端渲染的，改个交互要整页刷新
    • 表设计得很随手，字段想到哪加到哪，没有一张是认真画过的
    • 命名风格前后不统一，一个模块里三种写法
    • 没有状态机，房态全靠 if 硬改；没有事务边界，出错了就出错
    • 分层写是写了，但 Service 里塞满了业务逻辑之外的东西

    如果这是别人写的代码，我大概会直接说"这个得重写"。

    但它是我第一个从零写到线上的项目。

    建库、写实体、画页面、打 Docker 镜像、部署上线，第一次把一整套链路完整走下来。那个项目现在看是丑，可当时每解决一个问题都是真的高兴。

    所以还是不舍得丢掉。

    于是重做了一版

    最后还是没拿旧版去交，推倒重来。

    这次基于 芋道 yudao-boot-mini 做二次开发。有一说一，框架就是方便：权限、租户、代码生成、定时任务、文件存储这些脏活累活它全包了，我只需要专注在酒店业务本身。

    重做之后的规模：

    | 部分 | 数量 | | --- | --- | | 业务表 | 33 张 | | 后端模块 | 27 个 | | Java 文件 | 316 个 | | 管理后台页面模块 | 29 个 | | C 端 | uni-app（H5 / 小程序） |

    业务上补了真正缺的东西：账务账页（Folio）、夜审与营业日、收益定价、协议单位应收、清洁任务与房态的联动。房态也不再是一个字段，而是一条链 —— 退房自动生成清洁任务，保洁完成、领班核实之后房间才回到空闲。

    源码推到了 github.com/Daylight-by/hotel-pms。

    不完善的地方

    时间赶，所以也得说清楚：这版也远称不上完美。

    • 演示数据是凑出来的，不是为了展示业务造的
    • 部分模块的边界情况没覆盖全，比如并发下的房态抢占
    • 公安上传、门锁、OTA 对接只做了标准适配层，靠模拟数据演示 —— 真接需要对接方资质，那不是代码能解决的事
    • 报表那块还停留在"能看"，谈不上"能用"

    但至少，现在是能看的了。

    写在最后

    半年过去，计划没完成，代码倒是从"能跑"变成了"能用"。

    写下来是怕自己再过半年又忘了这段。这次争取别再停半年了。
